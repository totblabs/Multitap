# 할당된 VM의 Host 일괄 업데이트

Windows 클라이언트에서 로그인한 계정에 할당된 VM(과 로컬 PC)의 Host를 이 서버의 최신 Host로 한꺼번에 업데이트한다. 관리자 역할은 필요 없다. 관리자 콘솔의 "모든 Host 업데이트"와 이전 버전 설치는 이 기능과 별개다.

## 여는 곳

헤더의 업데이트 확인 패널에서 **할당된 Host 일괄 업데이트**를 누른다(업데이트할 Host가 있으면 패널이 먼저 안내한다). 코드: `lib/ui/bulk_host_update_dialog.dart`(`showBulkHostUpdateDialog`), `lib/data/bulk_host_updates.dart`(`BulkHostUpdateController`).

## 동작

- 대화상자는 이 서버의 공개 카탈로그에서 최신 Host를 읽고, 현재 버전 → 설치할 버전, 변경 내역, 대상 목록을 보여 준다. 사용자가 대상을 고르고 확인해야 시작한다.
- 대상은 할당되어 있고, 서버가 업데이트를 제안하며, 제안 버전이 그 최신 버전이고 현재 버전보다 높은 Host뿐이다. 오프라인·미지원·업데이트 중인 Host는 고를 수 없다.
- 한 번 시작한 묶음의 버전은 고정된다. 서버가 `host_release_unavailable`을 돌려주거나 카탈로그가 바뀌면 남은 요청을 멈추고 다시 확인하라고 안내한다. 새 버전으로 조용히 바꿔 요청하지 않는다.
- 각 VM은 `POST /api/v1/desktops/:id/host-update` `{version, disconnectSessions}`로 요청한다. 클라이언트의 표시는 권한 근거가 아니다. 서버가 요청마다 로그인, 할당, 최신 릴리스(더 낮은 버전 불가), Host 상태를 다시 확인한다.
- 연결 중인 VM: 먼저 연결을 끊고 바로 업데이트하도록 요청한다(`disconnectSessions:true`). 일반 계정은 자신의 연결만 끊을 수 있으므로, 다른 사용자가 연결 중이면 서버가 `desktop_busy`(`other_user`)로 거절하고, 클라이언트는 그 VM을 "연결이 끝나면 업데이트"(`disconnectSessions:false`)로 다시 요청한다. 관리자 계정의 요청은 모든 연결을 끊는다. Windows는 재시작하지 않는다.

## 요청 간격과 재시도

- 요청은 한 번에 하나씩, 단조 시계 기준 최소 3.1초 간격으로 보낸다. 서버의 계정별 제한(60초에 20회)을 넘지 않기 위해서다.
- 정확히 429 `too_many_host_update_attempts`는 서버가 요청을 처리하기 전에 거절한 것이므로 60초 기다린 뒤 최대 2번까지 다시 보낸다. 그동안은 "접수되지 않음"으로 표시한다.
- 그 밖의 네트워크 오류나 응답 유실은 같은 VM에 자동으로 다시 요청하지 않는다. 응답을 기다리는 POST가 있는 동안 다른 POST를 겹쳐 보내지 않는다.
- 개별 VM의 명확한 거절은 다음 VM으로 넘어가고, 401/403은 남은 목록을 멈춘다.
- 대기 중에는 언제든 중지할 수 있다. 중지와 닫기는 아직 보내지 않은 요청만 멈추며, 이미 접수됐거나 응답을 기다리는 요청을 취소됐다고 표시하지 않는다.

## 진행 표시

서버 접수, 연결 종료 대기, 다운로드, 검증, 설치, Host 재연결, 서버가 확인한 완료, Windows 재시작 필요, 결과 확인 필요, 실패를 VM마다 따로 표시한다. 버전 문자열이 같다는 이유만으로 완료로 추측하지 않는다. `result_unreported`는 설치 결과 확인 필요, `display_attention`은 설치 후 가상 화면 확인 필요로 표시한다.

접수된 작업이 있는 동안 할당 목록을 약 3초마다 다시 읽는다(브로커 푸시도 반영). 조회는 겹치지 않고 읽기만 한다. 토큰은 메모리에서만 쓰고 파일·로그·화면에 남기지 않는다.
