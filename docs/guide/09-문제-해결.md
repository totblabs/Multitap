# 9. 문제 해결

[가이드 목차](README.md) · [이전: 업데이트](08-업데이트.md) · [다음: 보안 안내](10-보안-안내.md) · [English](en/09-troubleshooting.md)

화면에 나온 문구와 같은 항목을 찾으세요.
한 번 조치한 뒤 상태를 다시 확인하세요.

## 어디까지 됐는지부터 확인하세요

위에서부터 읽고, 처음 막힌 줄의 안내를 따르세요.
오류 문구가 있으면 아래의 같은 문구를 찾아보세요.

| 어디에서 막혔나요? | 먼저 할 일 |
| --- | --- |
| 서버를 처음 설치하는데 관리자 페이지가 안 열림 | [2장](02-서버-설치.md#2단계-설치-명령-실행)에서 서버 IP·실행 상태·접속 포트를 확인하세요. 서버에서 `sudo multitap status`로 상태와 주소를 봅니다. |
| 앱의 **연결 테스트** 실패 | [서버 주소와 로그인](#서버-주소와-로그인)에서 주소·인증서를 확인하세요. |
| 되던 앱과 Host가 모두 접속하지 못함 | 관리자가 [저장된 접속 설정을 읽지 못했을 때](#저장된-접속-설정을-읽지-못했을-때)를 확인하세요. |
| 서버 연결은 되지만 로그인 실패 | 관리자가 만든 Multitap 계정인지 확인하세요. Windows·Proxmox 비밀번호와 구분하세요. |
| 로그인했지만 내 데스크톱이 비어 있음 | 관리자에게 [데스크톱 배정](05-사용자와-VM-배정.md#처음-연결-확인) 확인을 요청하세요. |
| 데스크톱 카드에 Host 오프라인·화면 준비 오류 | [Host와 가상 화면](#host가-오프라인이거나-화면이-준비되지-않음)을 확인하세요. |
| 연결 창이 열렸지만 검은 화면 | [스트리밍 검은 화면](#스트리밍-화면이-검게-보임)을 확인하세요. |
| 화면은 나오는데 파일 복사·USB만 안 됨 | 툴바 **설정**의 **사용안내**에서 허용된 기능을 확인하세요. |
| Windows가 로그아웃되거나 잠겨 있음 | 카드의 **▾ → Console**로 로그인하거나 **⏻ → 다시 시작**을 하세요. |
| 보안 확인 창(UAC)을 누를 수 없음 | [보안 확인 창](#보안-확인-창uac이-떴을-때)을 확인하세요. |
| Console이 열리지 않거나 검은 화면 | [Console 문제](#console이-열리지-않거나-검게-보임)를 확인하세요. |

주소 설정을 바꾼 뒤에는 앱에서 **연결 테스트 → 저장**을 다시 진행하세요.

## 서버 주소와 로그인

| 보이는 문구 | 먼저 할 일 |
| --- | --- |
| **서버 주소를 찾지 못했어요.** | 주소의 철자와 인터넷 연결을 확인하세요. |
| **HTTPS로 안전하게 연결하지 못했어요.** | 서버 주소를 확인하고, 맞다면 관리자에게 알려 주세요(인증서 문제일 수 있습니다). |
| **서버가 시간 안에 응답하지 않았어요.** | 주소와 포트를 확인하고 다시 시도하세요. |
| **이 주소는 Multitap 서버가 아니에요.** | 관리자에게 받은 서버 주소인지 확인하세요. |
| **이 주소는 서버에 등록된 주소가 아니에요.** (`origin_not_allowed`) | 받은 주소의 HTTP·HTTPS 구분과 포트를 다시 확인하고, 맞다면 관리자에게 알려 주세요. |
| **서버에서 HTTP 연결이 꺼져 있어요.** | HTTPS 주소를 쓰거나 관리자에게 요청하세요. |
| **이 HTTP 주소는 서버 초기 설정에만 쓸 수 있어요.** | 관리자가 **서버 접속 설정**을 마친 뒤에 연결할 수 있습니다. |
| **이 주소가 서버의 설정과 맞지 않아요.** | 받은 주소와 포트를 다시 확인하고, 맞다면 관리자에게 알려 주세요. |

### 관리자가 확인할 때

1. 관리자 페이지 왼쪽 메뉴의 **서버 접속 설정**을 여세요.
2. 사용자가 입력한 주소를 허용 주소와 비교하세요.
3. 주소가 없으면 같은 화면에서 추가하고 **연결 테스트** 뒤 **변경 저장**을 누르세요.
4. 클라이언트에서 **연결 테스트**를 다시 하세요.

HTTPS 프록시를 쓰는데 `403 http_disabled`가 나오면 신뢰할 프록시 설정이 빠졌을 수 있습니다.
**서버 접속 설정**의 **신뢰할 프록시 IP**에 실제 프록시의 주소가 있는지 확인하세요. 프록시가 서버와 같은 컴퓨터에 있으면 **프록시가 이 서버에 있어요**를 누릅니다.

저장한 뒤 **새 주소로 서버에 닿지 못해 이전 설정으로 돌아갔어요**가 나오면, 서버가 그 주소로 자기 자신에게 연결하지 못한 것입니다.
주소, DNS, 프록시, 공유기 포트 포워딩을 확인하세요. 공유기가 안쪽에서 자기 공인 주소로 돌아오는 연결을 넘겨주지 않아도 이렇게 됩니다.

관리자 페이지에 들어갈 수 없으면 **Linux 서버**에서 확인하고 고칩니다.

```sh
sudo multitap status
sudo multitap address
sudo multitap address http://10.0.0.10:18480
```

`multitap status`는 서버가 응답하는지, 지금 주소, 남은 디스크 공간을 보여 주고, 응답하지 않으면 서버 기록의 마지막 줄을 함께 보여 줍니다.
`multitap address <주소>`는 그 주소로 바꾸고 서버를 다시 시작합니다([2장](02-서버-설치.md#2단계-host와-앱이-사용할-주소-확인)).

### 저장된 접속 설정을 읽지 못했을 때

앱과 Host가 모두 접속하지 못하고, **서버 접속 설정**에 **저장된 접속 설정을 읽지 못해, 서버가 관리자 페이지만 연 채로 켜졌어요**가 보이는 경우입니다.
서버가 주소 없이 켜진 상태라 관리자 페이지만 열리고, 앱·Host·다운로드는 거절됩니다. 둘 중 하나로 고칩니다.

1. 브라우저로 `http://<서버 IP>:18480`을 열어 로그인하고, **서버 접속 설정**에서 주소를 다시 넣은 뒤 **연결 테스트**와 **변경 저장**을 누르세요.
2. 또는 **Linux 서버**에서 저장된 설정을 지우고 새로 정하세요.

   ```sh
   sudo multitap address --reset http://10.0.0.10:18480
   ```

`sudo multitap status`도 같은 내용과 관리자 페이지 주소를 보여 줍니다.
이 관리자 페이지 주소는 Docker 포트를 서버 안에서만 열었거나(`MULTITAP_PUBLISH_PORT=127.0.0.1:18480`), 직접 작성한 compose 파일에 `MULTITAP_SERVER_ADDRESS`가 없으면 열리지 않습니다. 그때는 2번의 명령을 쓰세요.

인증서 오류를 무시해서 연결하지 마세요.
같은 내부망에서 HTTP로 운영하려면 [보안 안내](10-보안-안내.md)를 먼저 확인하세요.

## Host가 오프라인이거나 화면이 준비되지 않음

| 표시 | 사용자 | 관리자 또는 해당 Windows를 관리하는 사람 |
| --- | --- | --- |
| **Host 오프라인** | 전원 상태를 확인하세요. | Host 설정에서 서버 연결과 서비스 상태를 확인하세요. |
| **관리자 승인 대기** | 관리자에게 승인 확인을 요청하세요. | 두 화면의 확인 코드를 비교한 뒤 Host 연결 요청을 승인하세요. |
| Host 설정에 **이 Windows는 등록된 다른 데스크톱을 복사한 것 같아요.** | 관리자에게 알려 주세요. | 복사한 VM입니다. Host 설정의 **서버 연결**에서 **연결 요청**을 누르고, 새 Host처럼 승인하세요([4장](04-Host-설치.md#복사한-vm)). |
| **가상 화면이 준비되지 않았어요** | 관리자에게 Host 점검을 요청하세요. | Host 설정의 **가상 화면**에서 상태와 필요한 조치를 확인하세요. |
| **Host가 화면을 구성하고 있어요** | 구성이 끝난 뒤 다시 연결하세요. | 오래 멈추면 Host 설정의 **진단**을 확인하세요. |
| **Windows 계정 확인이 필요해요** | 관리자에게 Windows 계정 확인을 요청하세요. | Host 설정의 **Windows 로그인**에서 저장한 계정을 확인하세요. |
| **Windows에 로그인돼 있지 않아요** 또는 **Windows가 잠겨 있어요** | 카드의 **Console**을 열어 로그인하거나 잠금을 푸세요. **다시 시작**하면 자동으로 로그인됩니다. | Host의 **Windows 로그인**에 계정이 저장돼 있는지 확인하세요. |
| **Windows를 다시 시작해야 해요** | 열려 있는 작업을 저장한 뒤 **다시 시작**하세요. | 표시된 원인을 확인한 뒤 해당 Windows를 다시 시작하세요. |
| **이전 연결을 정리하고 있어요** | 끝나면 연결할 수 있습니다. 잠시 기다리세요. | 반복되면 Host의 **진단**에서 화면 복구 상태를 확인하세요. |

Host 설정에 **서비스 시작**이 보이고 서비스가 중지돼 있다면 그 버튼으로 시작하세요.
상태가 바뀐 뒤 클라이언트의 **새로고침**을 누르세요.

## 관리자 페이지의 Proxmox 경고

관리자 페이지 위쪽과 **홈**의 **지금 할 일**에 Proxmox 인증서나 토큰 경고가 나오면 [3장의 인증서와 토큰 경고](03-Proxmox-연결.md#인증서와-토큰-경고)를 따르세요.
**Proxmox 인증서가 바뀌었어요**나 **Proxmox 인증서가 만료됐어요**가 나오면 전원·Console·상태 확인이 멈춘 상태입니다. 바로 고치세요.

## 스트리밍 화면이 검게 보임

1. 데스크톱 창에 오류 안내가 있는지 확인하세요.
2. 오류가 있으면 그 문구에 해당하는 조치를 하세요.
3. 검은 화면이 계속되면 연결을 닫고 **새로고침**을 누르세요.
4. 다시 연결해도 같으면 관리자에게 Host의 **가상 화면**과 **진단** 확인을 요청하세요.

서비스가 실행 중이라는 표시만으로 화면 전송까지 준비됐다고 볼 수는 없습니다.
화면에 원인이 표시되지 않으면 드라이버를 임의로 지우지 말고 진단을 확인하세요.

## Console이 열리지 않거나 검게 보임

Console은 Proxmox VM의 기본 화면인 QEMU 화면을 보여 줍니다.
Console을 여는 동안에는 이 기본 화면 하나만 켜지고, 닫으면 다른 화면이 돌아옵니다.
로컬 PC에는 Console이 없습니다.

| Console에 보이는 문구 | 할 일 |
| --- | --- |
| **콘솔에 보일 화면이 없어요** | VM의 Proxmox 디스플레이가 없음(none)이나 직렬 터미널(serial)이거나, 패스스루한 GPU가 주 VGA인 경우입니다. 관리자가 Proxmox에서 VM의 **Hardware → Display**를 **Standard VGA**로 바꾸고 VM을 다시 시작하세요. |
| **로그인 화면이 콘솔에 보이지 않는 다른 화면에 있을 수 있어요.** | PCI 장치(GPU 등)를 붙인 VM이 로그아웃되거나 잠긴 경우입니다. 데스크톱을 **다시 시작**하세요. 자동으로 로그인됩니다. |
| **다른 원격 연결이 사용 중이에요** | 쓰고 있는 스트리밍 연결을 끊은 뒤 Console을 다시 여세요. |
| **이전 연결을 정리하고 있어요** | 잠시 후 다시 연결하세요. |
| **원래 VM 화면이 꺼져 있어요** | 관리자에게 화면 복구 결과 확인을 요청하세요. |
| **원래 화면의 복구 정보가 없어요** | 관리자에게 VM 화면 상태 확인을 요청하세요. |
| **VM 화면 구성이 바뀌었어요** | 관리자에게 VM 디스플레이 설정 확인을 요청하세요. |
| **VM 콘솔이 꺼져 있어요** | 관리자에게 QEMU 콘솔 설정 확인을 요청하세요. |
| **콘솔에 연결할 권한이 없어요** | 관리자에게 데스크톱 배정과 **Proxmox 연결**의 **긴급 콘솔 권한** 확인을 요청하세요. |
| **콘솔 인증이 끝났어요** | 창을 닫고 앱의 카드에서 Console을 다시 여세요. |
| **화면이 아직 안 보여요. 계속 검은 화면이면 다시 연결하세요.** | Console을 다시 연결하세요. |

**콘솔 연결됨**은 Windows 로그인이나 정상 화면 표시를 보장하지 않습니다.
다시 연결한 뒤에도 검은 화면이면 관리자에게 QEMU 화면과 GPU 구성을 확인해 달라고 요청하세요.

## 보안 확인 창(UAC)이 떴을 때

일반 바탕 화면에 뜨는 보안 확인 창과 관리자 권한으로 실행한 창은 스트림 안에서 보고 조작할 수 있습니다.
일반(표준) Windows 계정으로 쓰는 데스크톱에서도 같습니다. Windows의 UAC 설정은 바꾸지 않습니다.

아직 안 되거나 확인하지 못한 경우는 다음과 같습니다.

| 경우 | 할 일 |
| --- | --- |
| 화면이 어두워지면서 뜨는 확인 창(Windows 기본 설정의 보안 화면) | 실제 환경에서 아직 확인하지 못했습니다. 조작이 안 되면 아래 안내를 따르세요. |
| **데스크톱에 보안 확인 창이 떠 있어요** 안내 화면 | 연결을 끊고 카드의 **Console**을 열어 응답하세요. |
| Windows가 로그아웃되거나 잠긴 상태 | 스트리밍하지 않습니다. **Console**이나 **다시 시작**을 쓰세요. |

## 소리가 들리지 않음

데스크톱의 소리는 항상 함께 나옵니다.

1. PC나 휴대폰의 음량을 확인하세요.
2. 데스크톱 카드에 **소리 없음**이 있으면 데스크톱에 소리 장치가 없는 상태입니다. 관리자에게 요청하세요.
3. 소리 장치가 이미 있다면 데스크톱의 Windows 소리 출력을 확인하세요.

소리 장치는 관리자가 Proxmox에서 추가합니다.
Proxmox 웹에서 VM의 **Hardware → Add → Audio Device**를 선택하세요.
Multitap 앱과 관리자 페이지에서는 소리 장치를 추가하지 않습니다.

**다시 시작 필요** 배지는 추가한 장치가 아직 적용되지 않았다는 뜻입니다.
Proxmox에서 VM을 종료했다가 다시 시작하세요.
Windows 안의 다시 시작만으로는 새 장치가 적용되지 않습니다.

로컬 PC의 소리 장치는 해당 PC의 Windows에서 확인하세요.

## 마우스 잠금과 게임 입력

| 증상 | 할 일 |
| --- | --- |
| 마우스가 데스크톱 화면에 잠김 | Windows 클라이언트에서 **Ctrl+Shift+Alt+Z**를 누르세요. |
| 새 연결에서 잠금이 풀려 있음 | 새 연결은 항상 꺼진 채 시작합니다. 필요할 때 같은 단축키나 툴바 **설정**에서 켜세요. |
| 게임에서 마우스가 움직이지 않음 | 관리자에게 해당 사용자·데스크톱의 USB 공유 권한 확인을 요청하세요. |
| Host의 USB 상태: **다른 프로그램이 USB 연결 기능을 쓰고 있어요.** | Host 설정의 **장치 → Multitap용으로 바꾸기** 안내를 확인하세요. |
| 커서 위치가 어긋남 | 서버·Host·클라이언트를 최신 버전으로 업데이트하세요. |

컨트롤러를 바꾸면 다른 프로그램의 USB 연결에 영향을 줄 수 있습니다.
변경 확인 창의 안내를 읽고 진행하세요.

USB 공유 권한과 Host의 USB 연결 기능이 준비돼야 가상 USB 마우스를 사용할 수 있습니다.
**마우스 잠금**을 켜는 것만으로 모든 게임의 호환성을 보장하지는 않습니다.

## 한/영 전환이나 한글 입력

1. 데스크톱 화면을 눌러 키보드 입력을 보낼 곳을 선택하세요.
2. Windows 클라이언트에서는 실제 키보드의 **한/영** 키를 누르세요.
3. Android에서는 키보드 위 키 줄의 **한/영**을 누르세요.
4. 계속 영문만 나오면 데스크톱의 Windows 한국어 입력기를 확인하세요.

### Console에서 한글 입력

휴대폰·태블릿의 Console에서는 **키보드** 버튼으로 입력한 한글과 영문이 VM의 실제 한/영 상태에 맞춰 들어갑니다.

| 보이는 문구 | 할 일 |
| --- | --- |
| **한글은 데스크톱에 로그인돼 있어야 보낼 수 있어요.** | 로그인 화면이나 잠금 화면에서는 영문·숫자·기호만 보냅니다. Windows에 로그인한 뒤 입력하세요. 로그인돼 있는데도 나오면 Host를 업데이트하세요. |
| **한/영 전환이 확인되지 않아 입력을 멈췄어요.** | 같은 글자를 다시 입력하세요. |

Console의 텍스트 클립보드는 한글 같은 문자를 보내지 않습니다. 긴 글은 **스트리밍**으로 연결해 복사하세요.

## Defender·SmartScreen이 설치를 막음

1. 경고 창에 나온 파일명과 탐지·차단 문구를 기록하세요.
2. **Windows 보안 → 보호 기록**에서 해당 항목을 확인하세요.
3. 관리자에게 파일의 버전과 가린 경고 내용을 전달하세요.
4. 관리자가 배포 경로와 최신 파일을 확인할 때까지 설치를 멈추세요.

경고만으로 오탐이라고 판단하지 않습니다.
Defender·SmartScreen을 끄거나 Multitap 폴더 전체를 예외로 등록하지 마세요.
프로젝트 배포 서명과 Windows의 게시자 신뢰는 서로 다릅니다([보안 안내](10-보안-안내.md)).

보호 기록 확인 방법은 [Microsoft 공식 안내](https://support.microsoft.com/en-us/windows/security/windows-security/protection-history-in-the-windows-security-app)를 보세요.

## 문의할 때 보낼 내용

1. 서버·Host·클라이언트 버전을 적으세요.
2. 문제가 생긴 시각과 직전에 누른 버튼을 적으세요.
3. 오류 문구를 그대로 적으세요.
4. 화면이나 로그의 주소·사용자명·설정 코드·비밀번호·토큰을 가리세요.

마이크와 카메라 전달은 지원하지 않습니다.
Mac·iOS·Linux용 클라이언트는 없고, Android에서는 USB 장치를 쓸 수 없습니다.
보안 취약점으로 보이는 내용은 공개 이슈에 적지 말고 [비공개 신고 안내](10-보안-안내.md#보안-문제-알리기)를 따르세요.
