# 8. 업데이트

[가이드 목차](README.md) · [이전: Android](07-Android.md) · [다음: 문제 해결](09-문제-해결.md) · [English](en/08-updates.md)

서버, Host, 클라이언트는 각각 업데이트합니다.
배지는 새 버전이 있다는 알림이며, 설치는 사용자가 선택한 뒤 시작합니다.

## 무엇을 업데이트하나요?

| 업데이트할 것 | 작업할 곳 | 이 장에서 볼 부분 |
| --- | --- | --- |
| PC의 Multitap 앱 | Windows PC | [Windows 클라이언트](#windows-클라이언트) |
| 휴대폰의 Multitap 앱 | Android 기기 | [Android 클라이언트](#android-클라이언트) |
| 데스크톱의 Host | 앱의 데스크톱 카드 **⋯** | [Host 한 대씩](#host--windows-클라이언트에서-한-대씩) |
| 중계·로그인 서버 | 관리자 페이지 + Linux 서버 | [서버 업데이트](#서버--설치-명령으로-설치한-서버) |

앱·Host·서버는 서로 다른 프로그램입니다.
앱만 업데이트해도 나머지가 함께 업데이트되는 것은 아닙니다.

> **진행 전:** 작업을 저장하세요. 서버나 Host를 업데이트하면 원격 연결이 잠시 끊길 수 있습니다.

## 서버 — 설치 명령으로 설치한 서버

**작업 위치: 관리자 페이지에서 버전을 확인한 뒤, Linux 서버에서 실행**

2장의 설치 명령으로 설치한 서버는 `multitap update` 한 줄로 올립니다.

1. 관리자 페이지 왼쪽 메뉴의 **업데이트**를 여세요.
2. **업데이트 확인**을 누르세요.
3. 새 버전의 변경 내역을 확인하세요.
4. **Linux 서버**에서 다음 명령을 실행하세요.

   ```sh
   sudo multitap update
   ```

   최신 대신 관리자 페이지에 안내된 버전으로 올리려면 버전을 붙입니다. 예: `sudo multitap update 1.2.3`

5. 관리자 페이지를 다시 열어 실행 중인 버전을 확인하세요.

`multitap update`는 다음 순서로 진행합니다.

1. 새 버전의 서버 이미지를 받습니다. 받지 못하면 지금 서버를 그대로 둡니다.
2. 데이터 볼륨 전체를 `/opt/multitap/backups`에 백업합니다.
3. 새 버전의 `compose.yaml`과 `multitap` 명령으로 바꾸고 서버를 다시 시작합니다.
4. 새 버전이 응답하기를 기다립니다. 응답하지 않으면 이전 버전으로 되돌립니다.

**완료 확인:** **✔ 1.2.3 버전으로 올렸어요. 데이터는 그대로예요.**(1.2.3 자리에 새 버전)가 나오고, 새 버전으로 로그인되고, 기존 사용자·데스크톱 배정이 남아 있습니다.
평소 쓰는 데스크톱에도 한 번 연결해 보세요.

관리자 페이지의 **업데이트**에 나오는 `docker compose` 명령은 Compose를 직접 쓰는 설치용입니다.
설치 명령으로 설치한 서버는 `multitap update`를 쓰세요. `compose.yaml`도 함께 새 버전으로 바뀝니다.

계정, 데스크톱 배정, 서버의 비밀키와 다운로드는 데이터 볼륨에 남습니다.
**`docker compose down -v`를 실행하거나 데이터 볼륨을 삭제하지 마세요.**

서버가 올라오지 않으면 다음 명령으로 상태와 최근 로그를 확인하세요.

```sh
sudo multitap status
sudo multitap logs
```

로그를 공유하기 전에는 설정 코드, 주소와 비밀값을 가리세요.
프록시·HTTP 설정과 백업의 자세한 내용은 [Docker 배포 안내](../docker-deployment.md)를 보세요.

<details>
<summary>Docker Compose를 직접 쓰는 설치의 서버 업데이트</summary>

`compose.yaml`과 `.env`가 있는 폴더에서 진행합니다.

1. 관리자 페이지의 **업데이트**에서 새 버전과 실행 명령을 확인하세요.
2. [아래 백업 절차](#서버-업데이트-전-백업)로 `.env`와 데이터 볼륨을 보관하세요.
3. `nano .env`를 열어 `MULTITAP_VERSION`을 안내된 버전으로 바꾸세요.
4. 같은 Compose 폴더에서 다음 명령을 실행하세요.

   ```sh
   sudo docker compose pull && sudo docker compose up -d
   ```

5. 관리자 페이지를 다시 열어 실행 중인 버전을 확인하세요.

편집기는 `Ctrl+O`, Enter, `Ctrl+X` 순서로 저장하고 닫습니다.
버전은 관리자 페이지에 안내된 값을 그대로 사용하세요.
상태와 로그는 `sudo docker compose ps`, `sudo docker compose logs --tail=50 broker`로 봅니다.

</details>

### 서버 업데이트 전 백업

설치 명령으로 설치한 서버는 `multitap update`가 업데이트 전에 백업을 만듭니다.
따로 백업하려면 **Linux 서버**에서 실행하세요.

```sh
sudo multitap backup
```

서버를 잠깐 멈추고 데이터 볼륨 전체를 `/opt/multitap/backups/multitap-data-(버전)-(날짜).tar.gz`로 복사한 뒤 다시 켭니다.
먼저 사용자에게 알리고 열린 작업을 저장하게 하세요.

**완료 확인:** **✔ 데이터를 백업했어요:** 뒤에 파일 경로가 나옵니다.
백업에는 비밀키(`vault.key`)와 계정 정보가 들어 있습니다. root만 읽을 수 있고, 공개하거나 일반 사용자에게 공유하지 마세요.
`.env`는 백업 파일에 들어가지 않습니다. `/opt/multitap/.env`도 따로 보관하세요.

### 백업에서 되돌리기

설치 명령으로 설치한 서버는 `multitap restore`로 백업을 되돌립니다. **Linux 서버**에서 실행하세요.

```sh
sudo multitap restore /opt/multitap/backups/multitap-data-(버전)-(날짜).tar.gz
```

`multitap backup`이나 `multitap update`가 만든 복사본이면 데이터 볼륨 전체가 그때로 돌아갑니다.
관리자 페이지에서 받은 `.mtbk` 백업 파일도 같은 명령으로 되돌립니다. 이때는 백업 암호를 묻습니다([2장: 백업·복원](02-서버-설치.md#백업복원--서버-데이터를-파일-하나로)).

1. 파일을 확인하고 만든 때, 서버 버전, 계정·데스크톱·배정 수를 보여 줍니다. 여기까지는 아무것도 바뀌지 않습니다.
2. **복원할까요? [y/N]**에 `y`를 입력하세요. Enter만 누르면 취소됩니다.
3. 서버를 멈추고 지금 데이터를 `…-before-restore.tar.gz` 안전 백업으로 남깁니다.
4. 복원하고 서버를 다시 켠 뒤 응답을 기다립니다. 실패하면 안전 백업으로 되돌리고 이유를 보여 줍니다. 다시 시도하지는 않습니다.

**완료 확인:** **✔ 복원했어요.**가 나오고 서버가 응답합니다. 먼저 사용자에게 알리세요. 복원하는 동안 연결이 끊깁니다.
이 서버보다 새 버전에서 만든 백업은 되돌리지 않습니다. 먼저 `sudo multitap update`로 올리세요.
`.env`는 바뀌지 않습니다. 접속 주소도 그대로입니다.
스크립트에서는 `--yes`를 붙이면 묻지 않고, `.mtbk`의 백업 암호는 `MULTITAP_BACKUP_PASSPHRASE` 환경 변수로 줍니다.

<details>
<summary>Docker Compose를 직접 쓰는 설치의 백업 순서</summary>

Compose 파일이 있는 폴더(예: `~/multitap`)에서 진행합니다.
서버를 잠시 멈추므로 먼저 사용자에게 알리고 열린 작업을 저장하게 하세요.

**Linux 서버의 같은 터미널**에서 순서대로 진행하세요.

1. Compose 폴더로 이동하세요.

   ```sh
   cd ~/multitap
   ```

2. 백업할 공간이 충분한지 확인하세요.

   ```sh
   df -h .
   ```

3. 다른 사용자가 읽을 수 없는 새 백업 폴더를 만드세요.

   ```sh
   MULTITAP_BACKUP_DIR=$(mktemp -d "$HOME/multitap-backup-XXXXXXXX")
   ```

   오류가 나오면 여기서 멈추세요. 백업 폴더를 만들기 전에는 서버를 중지하지 마세요.

4. 서버를 잠시 멈추세요.

   ```sh
   sudo docker compose stop broker
   ```

5. 데이터 전체를 백업 폴더로 복사하세요.

   ```sh
   sudo docker compose cp broker:/var/lib/multitap "${MULTITAP_BACKUP_DIR:?}/data"
   ```

6. 설치 설정도 복사하세요.

   ```sh
   cp .env compose.yaml "${MULTITAP_BACKUP_DIR:?}/"
   ```

7. 파일이 들어갔는지 확인하세요.

   ```sh
   sudo ls -la "${MULTITAP_BACKUP_DIR:?}" "${MULTITAP_BACKUP_DIR:?}/data"
   ```

8. 기존 서버를 다시 켜세요.

   ```sh
   sudo docker compose start broker
   ```

9. 백업 폴더 위치를 확인해 따로 기록하세요.

   ```sh
   printf '%s\n' "$MULTITAP_BACKUP_DIR"
   ```

**완료 확인:** 설정 파일 두 개와 `data` 안의 `broker.sqlite`·`vault.key`를 포함한 데이터가 있습니다.
DB만 백업하면 저장된 Proxmox 토큰을 복구하지 못할 수 있습니다. 데이터 폴더 전체를 보관하세요.

복사 중 오류가 나면 업데이트를 멈추세요.
`sudo docker compose start broker`로 기존 서버를 켠 뒤 원인을 확인하세요.

백업에는 비밀키와 계정 정보가 들어 있습니다. 공개하거나 일반 사용자에게 공유하지 마세요.
폴더가 생겼다는 확인은 실제 복원 시험과 다릅니다. 중요한 운영 서버는 별도 환경에서 복원도 확인하세요.

이 복사 방식은 Docker의 [Compose cp](https://docs.docker.com/reference/cli/docker/compose/cp/)를 사용합니다.
중지된 컨테이너에서도 파일을 복사할 수 있습니다([Docker 공식 설명](https://docs.docker.com/reference/cli/docker/container/cp/)).

</details>

## Host — Windows 클라이언트에서 한 대씩

배정받은 데스크톱의 Host를 업데이트할 수 있습니다.
일반 사용자도 자기에게 배정된 데스크톱의 최신 Host를 설치할 수 있습니다.

1. 데스크톱 카드의 **⋯ → Host 업데이트**를 여세요.
2. 현재 버전, 새 버전과 **이번 버전에서 달라진 점**을 확인하세요.
3. 사용 중인 연결이 없으면 **업데이트**를 누르세요.

연결 중인 대상에는 다음 두 선택이 나옵니다.

| 선택 | 동작 |
| --- | --- |
| **끝나면 업데이트** | 연결이 모두 끝난 뒤 시작합니다. |
| **지금 업데이트** | 허용된 연결을 끊고 바로 시작합니다. |

일반 사용자는 자기 연결만 끊을 수 있습니다.
다른 사용자가 연결 중이면 **끝나면 업데이트**를 선택하거나 관리자에게 요청하세요.

## Host — Windows 클라이언트에서 여러 대

1. 목록 위쪽의 **업데이트 확인**을 누르세요.
2. **Host 일괄 업데이트**를 누르세요.
3. 업데이트할 데스크톱을 선택하세요.
4. 연결 종료 안내를 읽으세요.
5. **선택한 N대 업데이트**를 누르세요.
6. 대상별 진행 상태와 설치 결과를 확인하세요.

내 연결은 끊고 바로 업데이트합니다.
일반 사용자에게 배정된 대상에 다른 사용자가 연결 중이면 그 연결이 끝난 뒤 진행합니다.
관리자 계정으로 요청하면 대상의 연결을 모두 끊을 수 있습니다.

**남은 요청 중지**는 아직 보내지 않은 요청만 멈춥니다.
이미 접수된 업데이트는 계속 진행합니다.

## Host — Android와 관리자 페이지

| 여는 곳 | 선택 | 사용 중인 대상 |
| --- | --- | --- |
| Android의 데스크톱 카드 **⋯ → Host 업데이트** | 변경 내역 확인 후 **업데이트** | 연결이 끝난 뒤 시작합니다. |
| 관리자 페이지 **데스크톱 → 해당 데스크톱**의 **Host 업데이트** | **업데이트**, 또는 **연결이 끝나면 업데이트** | **지금 업데이트(연결 끊김)** 버튼도 사용할 수 있습니다. |
| 관리자 페이지 **업데이트**의 **N대 모두 업데이트** (또는 **데스크톱**의 **업데이트** 표시) | 접속 중인 사람을 확인한 뒤 **연결을 끊고 N대 업데이트** | **접속 안 한 N대만**을 고르면 연결을 끊지 않습니다. |

Android에는 Host 일괄 업데이트가 없습니다.
배정되지 않은 대상까지 관리하는 작업은 관리자 페이지에서 진행하세요.

### Host 업데이트 뒤 다시 연결

Host 업데이트는 Windows를 자동으로 다시 시작하지 않습니다.
**Windows 다시 시작 필요**나 추가 확인 안내가 나오면 내용을 확인하세요.

업데이트 때문에 끊긴 Windows·Android의 스트리밍 화면은 Host가 돌아오기를 최대 10분 기다리며 자동으로 다시 연결을 시도합니다.
기다리는 동안 데스크톱 창을 열어 두세요.
시간이 지났거나 **기다리기 취소**를 눌렀다면 업데이트 완료 후 **다시 연결**을 누르세요.

## Windows 클라이언트

1. 목록 위쪽의 **새 버전** 표시나 업데이트 확인 버튼을 누르세요.
2. 변경 내역을 읽으세요.
3. **업데이트 받기**를 누르세요.
4. 파일 확인이 끝나면 **다시 시작해서 업데이트**를 누르세요.
5. Windows의 관리자 권한 요청을 확인하세요.

열린 연결이 있으면 **연결 끊고 업데이트** 확인이 나옵니다.
연결은 모두 끊기지만 데스크톱과 실행 중인 작업은 그대로 유지됩니다.
업데이트 뒤 앱이 다시 열리면 새 버전을 확인하세요.

## Android 클라이언트

1. 목록 위쪽의 **업데이트 확인**을 누르세요.
2. 변경 내역을 읽고 **업데이트**를 누르세요.
3. **받고 설치**를 누르세요.
4. 설치 허용 안내가 나오면 **설정 열기**를 누르세요.
5. Android 설정에서 Multitap의 **알 수 없는 앱 설치**를 허용하세요.
6. 앱으로 돌아와 **받고 설치**를 누르세요.
7. Android 설치 화면에서 **업데이트**를 누르세요.
8. 설치가 끝나면 앱을 다시 여세요.

앱 데이터와 로그인 설정은 유지됩니다.
