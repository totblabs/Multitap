# 2. 서버 설치와 기본 설정 — Docker

[목차](README.md) · [이전: 소개](01-소개.md) · [다음: Proxmox 연결](03-Proxmox-연결.md) · [English](en/02-server-install.md)

**목표:** PC의 브라우저에서 Multitap 관리자 화면에 로그인합니다.
명령 한 줄로 Debian이나 Ubuntu에 설치합니다. 처음에는 Windows VM 한 대를 연결하는 데 집중하세요.

## 먼저, 명령을 어디에 입력하나요?

| 이 장의 표시 | 열어 둘 곳 |
| --- | --- |
| **Linux 서버** | 서버에 SSH로 접속한 터미널, 또는 Proxmox에서 해당 **CT·VM → Console** |
| **PC** | 지금 사용하는 PC의 브라우저 |

**Proxmox 노드의 Shell과 Linux CT·VM의 Console은 다릅니다.**
이 장의 명령은 **Multitap을 설치할 Linux 안에서** 실행하세요.

명령 상자의 내용만 복사하세요. `sh` 같은 설명 글자는 입력하지 않습니다.
비밀번호를 입력할 때 글자나 `*`가 보이지 않아도 입력되고 있습니다.

> `10.0.0.10`과 `vdi.example.com`은 예시입니다.
> 자신의 서버 IP와 도메인으로 바꾸세요. 처음 설정은 믿을 수 있는 내부망에서 진행하세요.

## 서버 설치

먼저 Linux에 Multitap 서버를 설치하고 실행합니다.
서버가 실행되면 아래의 **서버 기본 설정**으로 넘어갑니다.

### 1단계. Linux 준비 — Proxmox CT 또는 VM

**작업 위치: Proxmox 웹, 그다음 Linux 서버**

1. Debian 또는 Ubuntu가 설치된 CT나 VM을 준비하세요. x86_64(amd64)만 됩니다.
   VM이 더 안전하고, CT가 더 가볍습니다. CT 안의 Docker는 CT의 nesting 기능에 기대는데, Proxmox나 Docker를 업데이트한 뒤 CT 안의 컨테이너가 시작되지 않은 사례가 있습니다. 오래 쓸 서버라면 VM을 권합니다.
2. CT라면 Proxmox에서 **CT → 옵션 → 기능**의 **nesting**을 켜세요. 권한 없는 CT는 **keyctl**도 켜세요.
3. 기능을 바꿨다면 CT를 다시 시작하세요.
4. Linux에 root로 로그인하거나, `sudo`를 쓸 수 있는 계정으로 로그인하세요.
5. 서버가 인터넷에 연결되는지 확인하세요. Docker와 서버 이미지를 받습니다.

Docker는 미리 설치하지 않아도 됩니다. 설치 명령이 없으면 설치하고, 있으면 그대로 씁니다.

**완료 확인:** Linux 터미널에 로그인돼 있고, nesting이 켜진 CT 또는 VM입니다.

### 2단계. 설치 명령 실행

**작업 위치: Linux 서버**

명령은 CT나 VM 안에서 실행합니다. Proxmox 노드에서 실행하지 않습니다.

| 설치할 곳 | 들어가는 방법 |
| --- | --- |
| CT | Proxmox 노드의 **Shell**에서 `pct enter <CT 번호>`, 또는 Proxmox 웹의 **CT → Console** |
| VM | Proxmox 웹의 **VM → Console**. 붙여넣기가 안 되면 직접 입력하거나 VM의 IP로 SSH 접속. IP는 Console에서 `ip -4 a`로 확인 |

SSH에서 `Permission denied (publickey)`가 나오면 키만 받는 VM입니다. 클라우드 이미지로 만든 VM이 그렇습니다. Console에서 진행하세요.

root 터미널에서 아래 한 줄을 실행하세요.

```sh
curl -fsSL https://raw.githubusercontent.com/totblabs/Multitap/main/deploy/docker/install.sh | MULTITAP_LANG=ko bash
```

root가 아니면 `sudo`를 붙입니다.

```sh
curl -fsSL https://raw.githubusercontent.com/totblabs/Multitap/main/deploy/docker/install.sh | sudo env MULTITAP_LANG=ko bash
```

`curl: command not found`가 나오면 `apt update && apt install -y curl`로 설치한 뒤 다시 실행하세요. root가 아니면 두 명령 앞에 `sudo`를 붙입니다.

`MULTITAP_LANG=ko`는 안내를 한국어로 보여 줍니다. 빼면 Linux의 언어 설정을 따르고, 한국어가 아니면 영어로 나옵니다.

명령이 무엇을 하는지, 먼저 읽어 보고 실행하는 방법은 아래 [이 명령이 하는 일](#이-명령이-하는-일)에 있습니다.

설치는 네 단계로 진행합니다: **[1/4] 시스템 확인 → [2/4] Docker → [3/4] 서버 파일과 이미지 → [4/4] 서버 시작**.
중간에 두 가지를 묻습니다. 그냥 Enter를 누르면 첫 질문은 **예**, 둘째 질문은 **아니요**입니다.

| 질문 | 뜻 |
| --- | --- |
| **앱과 Host가 이 주소로 접속하게 할까요?** `http://서버IP:18480` | 같은 네트워크의 앱과 Host가 이 주소로 접속합니다. 암호화되지 않습니다. |
| **밖에서도 HTTP로 접속하게 할까요? (공유기 포트 포워딩)** `http://공인IP:18480` | `y`로 답하면 서버의 공인 IP를 HTTP 주소로 등록하고, 바뀌면 서버가 10분 안에 따라갑니다. 인터넷을 지날 때 암호화되지 않으므로 밖에서는 HTTPS 주소를 권합니다. 나중에 **서버 접속 설정**에서 켤 수 있습니다. 공인 IP를 찾은 때만 묻습니다. |

두 질문은 새 서버의 첫 주소만 정합니다. 그 뒤로 주소는 관리자 페이지의 **서버 접속 설정**에서 바꿉니다.

**완료 확인:** 마지막에 **✔ 설치를 마쳤어요**와 세 줄이 나옵니다.

```text
  ① 브라우저로 열기   http://10.0.0.10:18480
  ② 처음 로그인       admin / admin
  ③ 설정 코드         (일회용 코드)
```

이 세 줄은 다음 **서버 기본 설정**에서 씁니다. 설정 코드는 다른 사람에게 보내지 마세요.

**✖ 멈췄어요** 아래에 이유와 다음 할 일이 나옵니다.
설치 기록은 `/var/log/multitap-install.log`에 남습니다(root만 읽을 수 있고, 설정 코드는 기록하지 않습니다).

- **root로 실행해 주세요**: 위의 `sudo` 명령을 쓰세요.
- **이 CT는 nesting이 꺼져 있어…**: 아무것도 설치하기 전에 확인해서 멈춥니다. 안내에 나온 대로 nesting(권한 없는 CT는 keyctl도)을 켜고 CT를 다시 시작한 뒤 같은 명령을 다시 실행하세요.
- **…단계에서 명령이 실패했어요**: 실패한 명령과 기록의 마지막 줄을 함께 보여 줍니다. 그 줄에 이유가 있습니다.
- **서버 이미지를 받지 못했어요**: Docker가 알려 준 이유(권한 거절, DNS, 시간 초과 등)를 그대로 보여 줍니다.
- **이 배포판의 패키지에는 'docker compose'(Compose v2)가 없어요**: Docker 공식 저장소(`download.docker.com`)에 연결되는지 확인하고 다시 실행하세요.
- **Debian이나 Ubuntu에서만 설치할 수 있어요**: 다른 배포판에서는 [Docker 배포 문서](../docker-deployment.md)의 Compose 방식을 쓰세요.
- **이 CT에서 Docker 컨테이너를 실행하지 못했어요**: 1단계의 nesting(권한 없는 CT는 keyctl도)을 켜고 CT를 다시 시작한 뒤 같은 명령을 다시 실행하세요.
- **서버가 3분 안에 응답하지 않았어요**: 위에 나온 기록을 확인하세요. 다시 보려면 `sudo multitap logs`.

같은 명령을 다시 실행해도 안전합니다. 다 설치된 서버는 아무것도 바꾸지 않고, 중간에 멈춘 설치는 남은 설정과 데이터로 이어서 설치합니다.

</details>

<details>
<summary>자세히: 설치 옵션</summary>

- 서버 관리 명령 `multitap`을 설치합니다. 안내 언어는 `.env`에 기억해 두고 `multitap`도 같은 언어로 답합니다.
- 데이터(계정, 배정, Host 등록, 비밀키, 다운로드)는 Docker 볼륨 `multitap-broker-data`에 있습니다.

명령 앞에 붙일 수 있는 설정입니다(`MULTITAP_LANG=ko`처럼 `bash` 앞에 씁니다).

| 설정 | 뜻 |
| --- | --- |
| `MULTITAP_VERSION=1.2.3` | 최신 대신 이 버전을 설치 |
| `MULTITAP_LAN_HTTP=0` | 첫 질문에 **아니요**로 답하고 묻지 않음 (`1`은 **예**) |
| `MULTITAP_PUBLIC_HTTP=1` | 밖에서 접속하는 HTTP 주소를 묻지 않고 등록 (`0`은 묻지 않고 등록하지 않음). 터미널 없이 실행하면 `1`일 때만 등록 |

Docker Compose를 직접 쓰거나 다른 Linux에 설치하려면 [Docker 배포 문서](../docker-deployment.md)를 보세요.

</details>

#### 이 명령이 하는 일

설치 명령은 [`deploy/docker/install.sh`](../../deploy/docker/install.sh) 한 파일을 받아 bash로 실행합니다. 그 파일이 하는 일은 다음이 전부입니다.

- **먼저 확인합니다.** root인지, Debian이나 Ubuntu인지, x86_64인지 봅니다. CT라면 nesting이 켜졌는지도 봅니다. 하나라도 아니면 아무것도 설치하지 않고 멈춥니다. 이미 설치된 서버라면 아무것도 바꾸지 않고 끝납니다.
- **Docker를 준비합니다.** `docker compose`가 되면 있는 Docker를 그대로 씁니다. 없으면 Docker 공식 저장소(`download.docker.com`)를 apt에 추가해 설치하고, 거기서 받지 못하면 Debian·Ubuntu의 `docker.io` 패키지로 설치합니다. 필요한 `ca-certificates`, `curl`, `gnupg`도 설치하고, Docker가 부팅할 때 켜지게 합니다.
- **받습니다.** GitHub에서 최신 릴리스 번호를 확인하고, 그 릴리스 태그(`v<버전>`)에서 `compose.yaml`, `.env.example`, `multitap` 명령을 받습니다. 서버 이미지 `ghcr.io/totblabs/multitap-broker`는 GitHub의 컨테이너 저장소에서 받습니다.
- **만듭니다.** `/opt/multitap`(`compose.yaml`, `.env`, `backups` 폴더), `/usr/local/bin/multitap`, Docker 볼륨 `multitap-broker-data`, 서버 컨테이너 하나, 설치 기록 `/var/log/multitap-install.log`(root만 읽음)입니다. Docker 공식 저장소에서 설치했다면 그 저장소 설정(`/etc/apt/sources.list.d/docker.list`와 키)도 남습니다.
- **포트를 엽니다.** Docker가 TCP 18480(관리자 페이지, 앱, Host)과 UDP 18481(화면 전송)을 엽니다.
- **두 가지를 묻습니다.** 위 표의 두 질문입니다. 첫 질문에 예라면, 둘째 질문을 위해 `1.1.1.1`(Cloudflare)에 서버의 공인 IP를 한 번 묻습니다.
- **하지 않는 일.** Docker와 서버 컨테이너 말고는 서비스나 예약 작업을 만들지 않습니다. 로그인 계정, SSH 키, SSH 설정을 건드리지 않습니다. 사용 통계를 보내지 않고, 설치한 서버도 보내지 않습니다. 서버가 스스로 연결하는 곳은 아래 [서버가 스스로 연결하는 곳](#서버가-스스로-연결하는-곳)에 있습니다.
- **지우기.** `sudo multitap uninstall`은 서버 컨테이너와 `multitap` 명령을 지웁니다. 데이터 볼륨, `/opt/multitap`, Docker, 받은 서버 이미지는 남습니다.

#### 먼저 읽어 보고 실행하기

한 줄 명령은 받은 스크립트를 바로 실행합니다. 먼저 읽으려면 파일로 받아 읽은 뒤 실행하세요. 똑같이 설치되고, 같은 두 가지를 묻습니다.

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/totblabs/Multitap/main/deploy/docker/install.sh
less install.sh
MULTITAP_LANG=ko bash install.sh
```

root가 아니면 마지막 줄을 `sudo env MULTITAP_LANG=ko bash install.sh`로 실행합니다. `less`는 `q`로 닫습니다.
스크립트는 `main`에서 받고, 스크립트가 받는 파일은 설치할 릴리스의 태그에서 받습니다. 모든 작업은 스크립트의 마지막 줄에서 시작하므로, 한 줄 명령이 받다가 끊겨도 아무것도 설치하지 않습니다.

Multitap은 AGPL-3.0 오픈 소스이고, 설치 스크립트와 서버, 앱, Host의 코드를 이 저장소에서 모두 읽을 수 있습니다.

- 서버 이미지는 공개된 [GitHub Actions 작업](../../.github/workflows/broker-image.yml)이 릴리스 태그의 소스로 만들어 `ghcr.io`에 올립니다. 이미지에 함께 들어가는 앱·Host 설치 파일은 그 릴리스에 올린 파일입니다. 이미지를 만든 커밋은 `docker image inspect --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' ghcr.io/totblabs/multitap-broker:<버전>`으로 봅니다.
- 서버 컨테이너는 root가 아닌 사용자로, 읽기 전용 파일 시스템에서, Linux 권한(capability)을 모두 뺀 채 돕니다(`compose.yaml`).
- 관리자 페이지의 새 버전 알림은 프로젝트의 Ed25519 키로 서명돼 있고, 서버가 서명을 확인한 뒤에 보여 줍니다. `sudo multitap update`는 서버 이미지를 버전으로 받습니다. 이미지 자체에 서명이 있는 것은 아닙니다.
- Windows 설치 파일은 유료 코드 서명 인증서로 서명하지 않아서 Windows가 확인을 묻습니다([문제 해결](09-문제-해결.md#defendersmartscreen이-설치를-막음)).

| 서버 관리 명령 | 하는 일 |
| --- | --- |
| `sudo multitap status` | 실행 상태, 버전, 주소 |
| `sudo multitap logs` | 서버 기록 (Ctrl+C로 멈춤) |
| `sudo multitap code` | 처음 설정 코드 다시 보기 |
| `sudo multitap address` | 앱과 Host가 쓰는 주소 보기. 주소는 **서버 접속 설정**에서 바꿉니다 |
| `sudo multitap address <주소>…` | 관리자 페이지에 들어갈 수 없을 때 같은 주소 설정을 서버에서 바꾸기 |
| `sudo multitap public-ip [on\|off]` | 공인 IP 따라가기 켜기·끄기(**서버 접속 설정**의 같은 스위치). 없이: 지금 상태 |
| `sudo multitap update [버전]` | 백업한 뒤 새 버전으로 올리기 ([8장](08-업데이트.md#서버--설치-명령으로-설치한-서버)) |
| `sudo multitap backup` | 데이터 전체를 `/opt/multitap/backups`에 복사 |
| `sudo multitap restore <파일>` | 백업 되돌리기 ([아래 백업·복원](#백업복원--서버-데이터를-파일-하나로), [8장](08-업데이트.md#백업에서-되돌리기)) |
| `sudo multitap restart` · `stop` · `start` | 다시 시작·멈춤·시작. 다시 시작은 관리자 페이지의 **서버 정보 → 서버 다시 시작**으로도 됩니다 |
| `sudo multitap uninstall` | 서버를 멈추고 지움. 데이터는 남음 |

## 서버 기본 설정

서버 설치가 끝났습니다. 이제 **관리자 계정 → 접속 주소** 순서로 설정합니다.
이 설정까지 끝나야 Host와 클라이언트를 연결할 수 있습니다.

### 1단계. 첫 관리자 계정 설정

**작업 위치: PC의 브라우저**

1. 설치 화면의 ① 주소(`http://서버IP:18480`)를 주소 표시줄에 넣으세요.
2. **아이디**에 `admin`을 입력하세요.
3. **비밀번호**에 `admin`을 입력하세요.
4. **로그인**을 누르세요.
5. **설정 코드**에 설치 화면의 ③ 코드를 입력하세요.
6. **새 관리자 아이디**를 입력하세요.
7. **새 비밀번호**를 10자 이상 입력하세요.
8. **비밀번호 확인**에 같은 비밀번호를 입력하세요.
9. **계정 변경하고 다시 로그인**을 누르세요.
10. 새 관리자 계정으로 로그인하세요.

설정 코드를 다시 보려면 **Linux 서버**에서 실행하세요.

```sh
sudo multitap code
```

**완료 확인:** `admin / admin` 대신 새 계정으로 관리자 페이지에 들어갑니다.
아이디와 비밀번호를 둘 다 바꿔야 합니다.

> 최초 설정 전에는 서버를 다시 시작할 때마다 설정 코드가 바뀝니다.
> `multitap code`는 최신 코드를 보여 줍니다. 코드나 코드가 들어 있는 로그를 다른 사람에게 보내지 마세요.

### 2단계. Host와 앱이 사용할 주소 확인

Host·클라이언트 연결과 다운로드는 **서버 접속 설정**에 있는 주소로만 됩니다.
주소, 기본 서버 주소, 신뢰할 프록시 IP, 공인 IP 따라가기를 모두 이 화면에서 정하고, 서버가 스스로 적용합니다.

#### 같은 집·회사 내부망 — 설치 때 이미 적용됨

설치 때 첫 질문에 **예**(Enter)로 답했다면 `http://서버IP:18480`이 이미 적용돼 있습니다.

**작업 위치: PC의 관리자 페이지**

1. 왼쪽 메뉴의 **서버 접속 설정**을 여세요.
2. **HTTP** 주소에 `http://서버IP:18480`이 있는지 확인하세요.

**완료 확인:** PC에서 그 주소의 `/get/host`를 열면 Host 다운로드가 시작됩니다.

**아니요**로 답했거나 주소를 바꾸려면 같은 화면에서 바꿉니다.

1. 주소를 넣거나 고치세요. HTTPS와 HTTP 각각 4개까지 넣을 수 있습니다.
2. **연결 테스트**를 누른 뒤 **변경 저장**을 누르세요.
3. 서버가 접속 중인 연결을 끊고 새 주소로 다시 시작합니다. 관리자 페이지도 잠시 끊깁니다.
4. 서버가 새 주소로 자기 자신에게 닿는지 확인합니다. 닿지 못하면 이전 설정으로 돌아가고 화면에 알려 줍니다.

서버 IP로 만든 HTTP 주소는 Docker가 여는 포트(`18480`)를 써야 합니다. 화면에 그 포트가 나옵니다.

> **HTTP는 암호화하지 않습니다.** 로그인 정보와 화면이 그대로 전달됩니다.
> 인터넷에서 자주 쓴다면 도메인과 HTTPS를 쓰세요.

<details>
<summary>관리자 페이지에 들어갈 수 없을 때 — 서버에서 주소 정하기</summary>

주소를 잘못 저장해 관리자 페이지가 열리지 않거나, Docker가 여는 포트를 바꿔야 할 때 **Linux 서버**에서 실행하세요.
관리자 페이지와 같은 설정을 읽고 씁니다.

```sh
sudo multitap address
sudo multitap address http://10.0.0.10:18480
```

주소 없이 실행하면 지금 주소를 보여 줍니다. 주소를 넣으면 그 주소들이 지금 주소를 모두 대신합니다. 여러 개면 띄어서 씁니다.
HTTP 주소를 넣으면 Docker가 여는 포트도 그 주소의 포트로 맞춥니다.
공인 IP 따라가기가 켜져 있으면 따라가는 주소는 목록에 남습니다. 빼려면 먼저 `sudo multitap public-ip off`를 실행하세요.
서버를 다시 시작하고, 새 주소로 시작하지 못하면 전 설정으로 되돌립니다.
`sudo multitap address --help`에 기본 서버 주소와 신뢰할 프록시를 함께 정하는 방법이 있습니다.

</details>

Docker의 공개 포트는 UFW 같은 방화벽 규칙을 우회할 수 있습니다.
공유기·Proxmox 방화벽의 접근 범위도 확인하세요([Docker 공식 안내](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations)).

#### 밖에서 접속하기 — 공인 IP와 포트 포워딩

도메인 없이 밖에서 접속하는 간단한 방법입니다. 동작하지만 HTTP라서 암호화되지 않습니다. 밖에서 오래 쓸 거라면 아래의 HTTPS를 권합니다.

**작업 위치: PC의 관리자 페이지, 그리고 공유기**

1. **서버 접속 설정**의 HTTP 주소에서 **공인 IP 따라가기**를 켜고 저장하세요.
   서버가 공인 IP를 알아내 HTTP 주소로 등록하고, 10분마다 확인해 바뀌면 따라갑니다.
   설치 때 둘째 질문에 `y`로 답했다면 이미 켜져 있습니다.
2. 공유기 설정에서 **TCP 18480**과 **UDP 18481**을 Linux 서버의 IP로 포워딩하세요.
3. 서버에 방화벽이 있으면 같은 두 포트를 여세요.

포워딩하기 전에는 밖에서 들어오지 않습니다. 같은 네트워크는 그대로 됩니다.
공인 IP 따라가기는 다른 HTTP 주소가 하나 있어야 켤 수 있고, 공인 IP 주소는 기본 서버 주소가 될 수 없습니다.

서버에서도 같은 스위치를 켜고 끌 수 있습니다: `sudo multitap public-ip on`, `sudo multitap public-ip off`. 끄면 등록한 주소는 그대로 남습니다.

#### 인터넷에서 접속하기 — HTTPS

도메인·유효한 인증서·HTTPS 리버스 프록시가 필요합니다.
리버스 프록시는 HTTPS 연결을 받아 Multitap 서버로 전달하는 프로그램입니다.

<details>
<summary>HTTPS 설정 순서 — 프록시가 Linux 서버와 같은 컴퓨터에 있는 경우</summary>

1. 도메인의 DNS를 외부에서 접속할 수 있는 서버 주소로 설정하세요.
2. 프록시의 HTTPS 인증서를 설정하세요.
3. 프록시의 전달 주소를 `http://127.0.0.1:18480`으로 설정하세요.
4. `Host`, `X-Forwarded-Proto: https`와 WebSocket의 `Upgrade`·`Connection` 헤더를 전달하세요.
5. 프록시의 WebSocket 읽기 제한 시간을 충분히 길게 설정하세요.
6. 서버 방화벽에서 프록시의 TCP 443 접속을 허용하고, 공유기를 쓴다면 외부 TCP 443을 프록시로 전달하세요.

구체적인 nginx 설정은 [Docker 배포 문서](../docker-deployment.md#리버스-프록시-예-nginx)에 있습니다.

**PC의 관리자 페이지**에서 진행하세요.

1. **서버 접속 설정**의 HTTPS 주소 칸에 도메인을 넣으세요. 예: `https://vdi.example.com`
2. **신뢰할 프록시 IP**에서 **프록시가 이 서버에 있어요**를 누르세요. 프록시가 들어오는 주소가 목록에 들어갑니다.
3. **연결 테스트**를 누른 뒤 **변경 저장**을 누르세요.
4. PC 브라우저에서 실제 HTTPS 주소로 로그인하세요.

`https://vdi.example.com`의 도메인을 실제 도메인으로 바꿔야 합니다.
이미 사용하던 Host·앱도 새 주소에서 연결 테스트를 하고 저장해야 합니다.
HTTPS만 쓸 거라면 HTTP 주소를 지우고 공인 IP 따라가기를 끄세요.

프록시가 다른 컴퓨터에 있다면 `127.0.0.1` 전달 주소를 그대로 쓰면 안 됩니다.
브로커의 실제 주소로 전달하고, **신뢰할 프록시 IP**에는 브로커에서 보이는 실제 프록시 주소를 넣으세요.

HTTPS만 쓰면서 Docker 포트를 서버 안에서만 열려면 **Linux 서버**의 `/opt/multitap/.env`에서 `MULTITAP_PUBLISH_PORT=127.0.0.1:18480`으로 바꾸고 `sudo multitap start`를 실행하세요.
프록시 없이 TLS를 직접 쓰려면 [Docker 배포 문서](../docker-deployment.md#리버스-프록시-예-nginx)를 확인하세요.

</details>

### 3단계. UDP 화면 전송 — 공유기에서 포트만 전달

UDP는 화면·소리를 더 빠르게 전송하는 경로입니다.
앱과 Host는 자기가 접속한 서버 주소의 UDP 18481 포트로 보냅니다. 서버에서 따로 설정할 것은 없습니다.

1. 서버 방화벽에서 UDP 18481을 허용하세요.
2. 밖에서 접속한다면 공유기에서 UDP 18481을 Linux 서버로 전달하세요.

UDP가 닿지 않으면 화면은 WebSocket 경로로 갑니다. 조금 느릴 뿐 연결은 됩니다.
다음 경우에는 UDP를 쓰지 않습니다.

- Docker의 UDP 포트가 서버 안에서만 열려 있을 때
- 주소가 IPv6 숫자 주소일 때
- HTTPS 주소가 UDP를 전달하지 않는 다른 컴퓨터의 프록시나 터널을 가리킬 때

마지막 경우에는 UDP를 받을 주소를 `/opt/multitap/.env`에 따로 적을 수 있습니다. 두 줄을 모두 적어야 하고, 저장한 뒤 `sudo multitap start`를 실행합니다.

```dotenv
MULTITAP_UDP_HOST_RELAYS=udp.example.com:18481
MULTITAP_UDP_CLIENT_RELAYS=udp.example.com:18481
MULTITAP_UDP_MEDIA=on
```

> TCP 443과 UDP 18481은 별개입니다. UDP는 HTTPS 프록시와 별도로 전달하세요.

**완료 확인:** **서버 접속 설정**의 **UDP 화면 전송**에 지금 상태가 나옵니다. 스트리밍으로 연결한 뒤에는 **연결 품질**에서 UDP/TCP 경로를 확인합니다.

### 서버가 스스로 연결하는 곳

서버가 사용자의 요청 없이 밖으로 연결하는 곳은 다음뿐입니다.

| 연결하는 곳 | 언제, 왜 | 끄는 방법 |
| --- | --- | --- |
| `github.com`(프로젝트의 릴리스) | 관리자 페이지가 열려 있는 동안 최대 1시간에 한 번, 서명된 새 버전 정보를 확인 | `/opt/multitap/.env`에 `MULTITAP_DOCKER_UPDATE_FEED=off` |
| `1.1.1.1`(Cloudflare의 주소 확인) | **공인 IP 따라가기**가 켜져 있을 때만 10분마다, 서버의 공인 IP를 확인 | **서버 접속 설정**에서 공인 IP 따라가기 끄기 |
| 연결한 Proxmox | 데스크톱 목록·전원·Console을 위해 | Proxmox 연결을 지우기 |

설치 명령과 `multitap update`는 실행할 때 `github.com`, `ghcr.io`(서버 이미지), `download.docker.com`(Docker가 없을 때)에서 파일을 받습니다.
설치 명령은 둘째 질문을 위해 공인 IP를 한 번 확인합니다.

### 서버가 쓰는 메모리

서버 컨테이너는 메모리를 512 MB까지 씁니다. CT나 VM의 메모리를 늘려도 이 한도는 그대로입니다.
동시에 접속하는 사람이 많아 모자라면 `/opt/multitap/.env`에 `MULTITAP_MEMORY_LIMIT=1g`처럼 적고 `sudo multitap start`를 실행하세요.

### 백업·복원 — 서버 데이터를 파일 하나로

관리자 페이지의 **설정 → 백업·복원**에서 서버 데이터를 파일 하나로 내려받습니다.
서버를 잃거나 새 서버로 옮길 때 이 파일로 계정·배정·Host 등록·Proxmox 연결을 되돌립니다.

**백업 파일 만들기**

1. **백업 파일 만들기**를 누르고 백업 암호를 두 번 입력하세요. 12자 이상입니다.
2. 내 계정 비밀번호를 입력하세요. 2단계 인증을 쓰면 인증 앱 코드도 입력합니다.
3. 내려받은 `.mtbk` 파일과 백업 암호를 서로 다른 곳에 보관하세요.

파일은 백업 암호로 잠겨 있습니다. 암호를 잊으면 복원할 수 없고, 서버도 암호를 알려 줄 수 없습니다.

| 들어가는 것 | 들어가지 않는 것 |
| --- | --- |
| 계정과 비밀번호, 2단계 인증 | 지금 로그인해 있는 상태 |
| 데스크톱 배정과 공유 설정 | 진행 중이던 전원 작업, Host 연결 코드 |
| Host 등록, Proxmox 연결 | 클라이언트·Host 진단 기록(7일분) |
| 관리 기록, 사용 기록 | `.env`와 TLS 인증서 파일, 다운로드 파일 |

**복원**

1. 같은 화면에서 백업 파일과 백업 암호를 넣고 **파일 확인**을 누르세요.
   여기까지는 아무것도 바뀌지 않습니다. 만든 때, 만든 서버, 계정·데스크톱·Host 수를 보여 줍니다.
2. 내용을 확인하고 **이 백업으로 복원**을 누르세요.

복원하면 지금 데이터가 백업의 것으로 바뀌고, 접속 중인 사람은 모두 끊깁니다.
복원 뒤에는 백업에 있던 관리자 계정과 비밀번호로 로그인합니다.
서버는 복원 전 상태를 보관해 두고, 다시 켜진 서버가 정상이 아니면 되돌립니다.

- 서버 접속 설정은 지금 것을 그대로 씁니다. **서버 접속 설정도 복원**을 켰을 때만 백업의 주소 설정을 적용합니다.
- 등록된 Host는 서버 주소가 그대로면 스스로 다시 연결합니다. 주소가 달라졌다면 Host마다 새 주소로 바꾸세요.
- 새로 설치한 서버는 첫 관리자 계정 화면의 **백업에서 복원**으로 시작할 수 있습니다. 설정 코드가 필요합니다(`sudo multitap code`).

**Docker 설치에서 복원하기**

이 장의 설치 명령으로 설치한 서버는 관리자 페이지에서 파일 확인까지 하고, 복원은 서버에서 명령으로 합니다.
관리자 페이지의 복원 화면에도 이 명령이 나옵니다.

1. 백업 파일을 서버로 옮기세요. 예: `scp multitap-backup-20261110-0730.mtbk root@<서버 IP>:/root/`
2. **Linux 서버**에서 실행하세요.

   ```sh
   sudo multitap restore /root/multitap-backup-20261110-0730.mtbk
   ```

3. 백업 암호를 입력하세요. 입력한 글자는 화면에 보이지 않습니다.
4. 만든 때, 서버 버전, 계정·데스크톱·배정·Host 수를 확인하고 **복원할까요? [y/N]**에 `y`를 입력하세요.
   여기까지는 아무것도 바뀌지 않습니다. Enter만 누르면 취소됩니다.

`y`를 누르면 서버를 잠시 멈추고 지금 데이터 볼륨 전체를 `/opt/multitap/backups/…-before-restore.tar.gz`로 남긴 뒤 복원하고 다시 켭니다.
복원하거나 다시 켜는 중에 실패하면 그 안전 백업으로 되돌리고 이유를 보여 줍니다.

**완료 확인:** **✔ 복원했어요.**가 나오고, 백업에 있던 관리자 계정으로 로그인됩니다.

- 접속 주소와 다운로드 파일은 이 서버 것을 그대로 씁니다. 주소는 **서버 접속 설정**에서 바꿉니다.
- 새로 설치한 서버도 설치를 마친 다음 같은 명령으로 복원합니다.
- 이 서버보다 새 버전에서 만든 백업은 복원하지 않습니다. 먼저 `sudo multitap update`로 올리세요.
- `sudo multitap backup`으로 만든 데이터 볼륨 복사본도 같은 명령으로 되돌립니다([8장](08-업데이트.md#백업에서-되돌리기)).

## 다음 장으로 가기 전

- [ ] 새 관리자 아이디와 비밀번호로 로그인했습니다.
- [ ] **서버 접속 설정**에 Host·앱이 사용할 주소가 있습니다.
- [ ] 그 주소의 `/get/host`에서 다운로드가 시작됩니다.

여기까지 됐다면 [3장: Proxmox 연결](03-Proxmox-연결.md)로 이동하세요.
`sudo multitap status`의 **실행 중이고 응답해요**는 서버의 상태이며, 데스크톱 화면의 준비 완료를 뜻하지는 않습니다.

> 계정과 데스크톱 배정은 Docker 데이터 볼륨에 저장됩니다.
> `multitap uninstall`도 데이터를 남깁니다. `docker compose down -v`를 실행하거나 볼륨을 삭제하지 마세요.

Multitap을 완전히 지울 때는 Proxmox에 만든 전용 사용자와 역할도 지웁니다. `multitap uninstall`은 Proxmox를 건드리지 않습니다.
**Proxmox 노드의 Shell**에서 실행하세요. 이름은 Proxmox 웹의 **데이터센터 → 권한 → 사용자**와 **역할**에서 볼 수 있습니다.

```sh
pveum user delete multitap-<이름>@pve
pveum role delete Multitap-<12자리>
```

사용자를 지우면 그 사용자의 API 토큰과 권한도 함께 지워집니다.
