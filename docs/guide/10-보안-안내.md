# 10. 보안 안내

[가이드 목차](README.md) · [이전: 문제 해결](09-문제-해결.md) · [English](en/10-security.md)

서버는 로그인과 원격 연결을 중계합니다.
서버와 서버 운영자를 신뢰할 수 있는 환경에서 사용하세요.

## 처음 쓸 때 기억할 다섯 가지

1. 인터넷에서는 `https://` 주소를 사용하세요.
2. 처음 설치한 관리자 아이디와 비밀번호를 둘 다 바꾸세요.
3. Host를 승인할 때 두 화면의 확인 코드를 비교하세요.
4. 복사·USB 공유는 필요한 사용자와 데스크톱에만 허용하세요.
5. 비밀번호·설정 코드·토큰·백업 파일을 공개하지 마세요.

토큰은 프로그램이 비밀번호처럼 사용하는 비밀값입니다.
문의할 때는 오류 문구만 남기고, 비밀값이 들어 있는 부분을 가리세요.

## HTTPS와 HTTP

인터넷에서 쓸 때는 유효한 인증서가 있는 **HTTPS** 주소를 사용하세요.
주소의 이름과 인증서가 일치해야 합니다.

**HTTP는 로그인과 WebSocket 통신을 암호화하지 않습니다.**
비밀번호, 화면과 키 입력이 네트워크에서 노출될 수 있습니다.
HTTP는 믿을 수 있는 내부망에서 쓰세요. 공유기 포트 포워딩으로 밖에서 HTTP로 접속하는 것도 동작하지만, 이 내용이 인터넷을 그대로 지나갑니다. 밖에서 쓸 때는 도메인과 HTTPS를 권합니다.
설치 명령은 밖에서 오는 HTTP를 물어볼 때 Enter를 **아니요**로 받습니다.

앱의 HTTP 확인 창에 동의해도 암호화가 생기지는 않습니다.
서버 주소·포트와 운영자의 설정이 맞는지 확인하세요.

### 종단 간 암호화는 아닙니다

화면과 입력은 브로커·릴레이 서버를 거칩니다.
HTTPS는 클라이언트와 서버, Host와 서버 사이의 각 연결을 보호합니다.
클라이언트와 Host만 내용을 해독하는 **종단 간 암호화(E2E)** 기능은 제공하지 않습니다.

서버 운영자가 통신 내용에 접근할 수 없는 구조라고 생각하면 안 됩니다.
UDP 미디어의 암호화도 종단 간 암호화를 뜻하지 않습니다.

## 설치 직후 첫 설정

1. 설치 후 바로 관리자 페이지를 여세요.
2. `admin` / `admin`으로 로그인하세요.
3. 서버 로그의 1회용 설정 코드를 입력하세요.
4. 관리자 아이디를 새 값으로 바꾸세요.
5. 다른 서비스와 겹치지 않는 새 비밀번호를 정하세요.
6. Proxmox 연결과 접속 주소 설정을 완료하세요.

설정 코드는 서버에서 다음 명령으로 다시 볼 수 있습니다.

```sh
sudo multitap code
```

설정 코드는 서버 로그에만 나오며, 첫 설정을 마치는 데 필요합니다.
코드나 코드가 포함된 로그를 다른 사람에게 보내지 마세요.
설정 전에 서버를 다시 시작했다면 최신 로그의 코드를 사용하세요.

계정마다 **2단계 인증**(인증 앱의 6자리 코드)을 켤 수 있습니다.
관리자 페이지는 왼쪽 메뉴의 **계정 보안**에서, 앱은 **⚙** 설정의 **2단계 인증**에서 설정하고 복구 코드를 따로 보관하세요.
강한 비밀번호를 사용하고 관리자 계정을 공동으로 쓰지 마세요.

## Host 승인과 사용자 권한

1. Host 설정과 관리자 페이지에 나온 확인 코드를 비교하세요.
2. 요청한 Windows와 코드가 일치할 때만 승인하세요.
3. 같은 VM의 중복 요청이 있으면 요청 대상을 먼저 확인하세요.
4. 사용자에게 필요한 데스크톱만 배정하세요.
5. 필요한 복사·장치 공유만 켜세요.

공유는 **사용자 × 데스크톱**별로 적용하며, 새 배정은 아무것도 주고받지 않는 **기본**으로 시작합니다.
Host 업데이트 권한과 전원 조작 권한은 서로 다릅니다.
데스크톱을 배정받았다고 모든 전원 동작과 장치 공유가 허용되지는 않습니다.

### 기록되는 것

서버는 누가 언제 로그인하고 어느 데스크톱에 얼마나 연결했는지 기록하고, 관리자 페이지의 **모니터링**에서 보여 줍니다.
기록에는 접속한 곳의 IP 주소가 들어 있고 2년 동안 보관합니다. 계정을 삭제하면 그 계정의 로그인·연결 기록도 지워집니다.
**연결 시간**은 연결해 있던 시간이며 일한 시간과 같지 않습니다.

같은 데스크톱의 같은 Windows 계정을 함께 쓰면 그 계정의 파일과 프로그램을 공유합니다.
Multitap 계정만 나눈다고 Windows 안의 작업 공간이 분리되지는 않습니다.

## 업데이트 파일의 확인

| 대상 | 확인하는 것 |
| --- | --- |
| 공식 Windows 클라이언트·Host 업데이트 | 파일 크기, SHA-256과 프로젝트 자체 Ed25519 배포 서명 |
| 서버 업데이트 안내 | 고정된 공개키로 서명된 릴리스 정보 확인 |
| Android 업데이트 | 파일 크기·SHA-256과 기존 앱에 맞는 패키지 서명 확인 |

파일이나 서명 확인에 실패하면 설치를 멈추고 관리자에게 알려 주세요.
클라이언트는 로그인에 사용한 서버의 배포 목록에서 업데이트를 받습니다.
신뢰하는 서버 주소를 사용하세요.

<details>
<summary>프로젝트 서명과 Windows 코드 서명의 차이</summary>

Ed25519 배포 서명은 Multitap이 고정한 공개키로 공식 배포 파일을 확인하는 방법입니다.
Windows가 설치 파일의 게시자를 표시하는 Authenticode 코드 서명과는 별개입니다.
배포 파일에는 구매한 코드 서명 인증서가 없습니다.
배포 서명이 맞아도 SmartScreen 경고가 사라지거나 Windows가 게시자를 신뢰한다는 뜻은 아닙니다.

Docker의 서명된 업데이트 안내도 컨테이너 이미지 태그 자체를 서명한 것은 아닙니다.
운영자는 공식 배포 경로와 관리자 페이지가 안내하는 버전을 확인해야 합니다.

</details>

## 비밀번호·백업·로그

Windows 클라이언트는 **비밀번호 기억**을 선택한 경우에만 현재 Windows 사용자의 자격 증명 관리자에 비밀번호를 저장합니다.
공용 PC에서는 이 선택을 해제하세요.

서버 데이터 볼륨과 백업에는 계정 정보, 데스크톱 배정, 로그인·연결 기록과 서버의 비밀키가 들어 있습니다.
관리자만 접근할 수 있는 곳에 보관하세요.
`.env`, 백업, 로그와 화면을 공개 저장소나 공개 이슈에 올리지 마세요.

관리자 페이지에서 만든 백업 파일(`.mtbk`)은 백업 암호로 암호화되어 있습니다([2장: 백업·복원](02-서버-설치.md#백업복원--서버-데이터를-파일-하나로)).
파일만으로는 만든 때와 서버 버전만 보이지만, 암호가 약하면 추측될 수 있습니다. 길고 다른 곳에 쓰지 않은 암호를 쓰고, 파일과 암호를 따로 보관하세요.

## 보안 문제 알리기

**취약점의 재현 방법이나 비밀값을 공개 이슈에 적지 마세요.**
신고 범위와 처리 기준은 [보안 정책](../../SECURITY.md)을 먼저 확인하세요.

공식 GitHub 저장소에서 비공개로 신고합니다.

1. [저장소](https://github.com/totblabs/Multitap/security)의 **Security** 탭을 여세요.
2. **Report a vulnerability**를 누르세요.
3. 영향을 받는 구성요소와 버전을 적으세요.
4. 필요한 권한, 재현 순서와 예상 영향을 적으세요.
5. 실제 주소·비밀번호·토큰을 가린 뒤 제출하세요.

신고 내용은 저장소 관리자에게만 보입니다. GitHub에 로그인해 있어야 합니다([GitHub 공식 안내](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)).
이 프로젝트는 별도의 신고 메일을 안내하지 않습니다.
보안 수정은 최신 공개 버전을 대상으로 하며, 정해진 응답 시간은 보장하지 않습니다.

## Host가 Windows에 하는 일

- 가상 화면 드라이버는 Sunshine이 서명한 원본을 그대로 씁니다. Host 설정에서 설치를 마무리할 때 동의를 받고 그 서명 인증서 하나(코드 서명 전용)를 Windows 신뢰 저장소에 넣습니다. 다른 인증서는 넣지 않습니다.
- 테스트 모드, Defender 예외 같은 Windows 보안 설정은 바꾸지 않습니다. UAC 설정도 바꾸지 않습니다.
- 보안 확인 창과 관리자 권한 창의 입력은 본인이 잠그지 않은 세션의 본인 스트림에서만 Host 서비스가 전달합니다.
- Host에 저장한 Windows 비밀번호는 그 Windows 안에만 있고 Multitap 서버로 보내지 않습니다.
